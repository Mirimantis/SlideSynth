## Context

[BACKLOG.md:181](BACKLOG.md:181) item **8.17** asks: *"Verify multi-voice
perform + multi-layer tones + playback CPU on target hardware. Measure before
optimising."* Today there is no perf instrumentation — every existing
`performance.now()` call drives countdown / AFK / activity tracking, not
measurement. Optimization decisions for adjacent items (especially
[BACKLOG.md:175](BACKLOG.md:175) **8.15 Lite harmonies**) are blind without a
way to see CPU pressure live.

Per the codebase exploration, the worst-case audio load is dominated by
per-curve synth instantiation in playback
([src/audio/playback.ts:171](src/audio/playback.ts:171)–[src/audio/playback.ts:201](src/audio/playback.ts:201)):
one full ToneSynth graph per curve, with 1–3 oscillators per tone layer plus
an optional 4× oversampled WaveShaper for distorted tones. Curve rendering
has no viewport culling
([src/canvas/curve-renderer.ts:18](src/canvas/curve-renderer.ts:18)–[src/canvas/curve-renderer.ts:140](src/canvas/curve-renderer.ts:140)).
There is no voice limit anywhere.

The user wants a passive observer — like a game FPS HUD — toggled from the
Transport panel exactly the way the Pitch HUD already is. Toggling it does
**not** trigger a test or synthesize load; it just displays metrics for
whatever the app is currently doing. A heavy saved composition lives in the
repo so the user can deliberately push the engine when they want to. No
formal writeup ships — when data later motivates a fix, that becomes its own
backlog item.

## Approach

Two deliverables in one PR:

1. **Perf HUD** — toggleable from Transport, three-line readout in the
   top-right, mirrors the Pitch HUD pattern end-to-end (toggle, persisted
   AppState field, render-loop refresh). Purely observational.
2. **Stress fixture** — a saved heavy composition committed to the repo at
   `fixtures/stress-test.ssn` (or whatever extension the existing exporter
   produces) so the user can load it any time they want to see the HUD
   under known load.

## Implementation

### 1. Active-synth / oscillator counters — [src/audio/tone-synth.ts](src/audio/tone-synth.ts)

Add module-level counters that the HUD reads through getters:

```ts
let activeSynths = 0;
let activeOscillators = 0;

export function getActiveSynthCount(): number { return activeSynths; }
export function getActiveOscillatorCount(): number { return activeOscillators; }
```

Increment in `createToneSynth(...)` after the graph is built (by
`tone.layers.length` for oscillators, +1 for the synth itself). Decrement in
the synth's `stop()` / disposal path. Symmetry is critical — verify in test
step 3 that the counts return to 0 after Stop, otherwise the HUD will lie.

If `createToneSynth` doesn't currently have a single dispose entrypoint, add
one minor helper there at execution time.

### 2. Perf HUD module — `src/ui/perf-hud.ts` (new)

Mirror the Pitch HUD shape (markup at
[src/main.ts:208](src/main.ts:208), update at
[src/main.ts:2715](src/main.ts:2715)-ish, CSS at
[styles/main.css:499](styles/main.css:499)).

```ts
export interface PerfHudMetrics {
  frameMsP50: number;
  frameMsP99: number;
  synthCount: number;
  oscillatorCount: number;
  voiceCount: number;       // active perform planchettes
  audioBaseLatencyMs: number;
}
export function createPerfHud(el: HTMLElement) {
  return {
    setVisible(v: boolean) { ... },
    refresh(m: PerfHudMetrics) { ... },
  };
}
```

Three text rows (monospace, fixed-width slots — same layout-stability fix
that 7.3 applied to the Pitch HUD):

- `Frame  14.2 / 28.0 ms` (p50 / p99 over rolling ~2 s)
- `Synths 47   Oscs 89   Voices 5`
- `Audio  5.8 ms latency`

### 3. Frame-time rolling window — [src/main.ts](src/main.ts)

In the render loop ([src/main.ts:2766](src/main.ts:2766)-ish), measure the
delta between consecutive `requestAnimationFrame` callbacks with
`performance.now()`. Maintain a ring buffer of size
`Math.ceil(2000 / 16) = 125` (≈2 s at 60 fps). Each frame: push the latest
delta, evict the oldest. Compute p50/p99 only when the HUD refresh runs
(sort a copy — 125 entries sorts in microseconds).

The HUD refresh runs each frame from the existing render loop, alongside
`updateCountdownOverlayDom` / `updateAfkWarningDom`
([src/main.ts:2808](src/main.ts:2808)–[src/main.ts:2810](src/main.ts:2810)).
Guard with `state.perfHudVisible` so it's a true no-op when off.

  hotkey-driven toggle keeps the checkbox in sync).
- **Hotkey: `!`** — add to the global keydown handler in
  [src/main.ts](src/main.ts) (search for the existing letter-key handlers

  No modifier conflict — `!` requires Shift+1 on most layouts and isn't

### 5. Voice / latency reads (from existing state)

- `voiceCount` — `state.performance.planchettes.length` (already in store).
- `audioBaseLatencyMs` — `getAudioContext().baseLatency * 1000`. Read once

- `synthCount` / `oscillatorCount` — call the new getters from
  [src/audio/tone-synth.ts](src/audio/tone-synth.ts).

### 6. Stress fixture — `fixtures/stress-test.ssn`

Author once via the app, then save with the existing File > Save flow
([src/export/json-export.ts](src/export/json-export.ts)) and commit the
output. Target shape (per the explorer's recommendation):

- 8 tracks, mixed tones from the built-in library:
  - 2 × Pure Sine (1 layer each)
  - 2 × Bright Square (1 layer)
  - 2 × Warm Pad (3 layers — peak per-voice cost)
  - 2 × Buzzy Saw (2 layers + 4× distortion)
- 15 curves per track (~120 active synths at playback).
- 240 beats at 120 BPM (4 minutes).
- Curves spread across the pitch range; some short bursts, some long sustained.

If hand-authoring proves tedious at execution, fall back to a small Node
script in `scripts/generate-stress-fixture.ts` that emits the JSON directly
using the serialization shape from
[src/export/json-export.ts](src/export/json-export.ts). Decide on the cheaper
path at execution time.

Verify the `fixtures/` directory isn't already gitignored — if it is, either
pick a different path or add an exception.

## Verification

1. **HUD show/hide.** Toggle the Transport checkbox; HUD appears/disappears
   top-right with three lines of metrics. Press `!` (Shift+1) — same toggle
   from the hotkey, and the checkbox `checked` reflects the new state.
2. **HUD persistence.** Reload the page; HUD visibility matches what was set
   before reload.
2a. **Hotkey doesn't fire while typing.** Focus the composition-name input,
   press `!`; HUD does not toggle (the existing 8.1 typing guard suppresses
   it).
3. **Counter integrity.** Play, then stop. After stop, `Synths` should
   return to 0 and `Oscs` to 0 (asymmetric increment/decrement = lying HUD;
   fix before shipping).
4. **Stress fixture loads.** Open `fixtures/stress-test.ssn` via File >
   Open; composition appears with the documented track/curve counts.
5. **HUD under load.** Press Play with the fixture loaded; HUD updates each
   frame; numbers move with what you're doing (more synths during playback,
   more voices during perform, frame ms higher under combined load).
6. **No performance regression when HUD is off.** Frame timing should be
   indistinguishable from main with `perfHudVisible = false` — the rolling
   buffer push is cheap, but the sort is gated to the refresh path.
7. `npm run typecheck` passes (modulo the three pre-existing failures noted
   in PR #52).
