# BACKLOG 8.21 — MIDI sustained note doesn't continue past loop wrap

> **Note for execution:** Per saved feedback, move this plan file to
> `<repo>/.claude/plans/8.21-midi-loop-wrap.md` before committing.

## Context

[BACKLOG.md:156](BACKLOG.md:156) item **8.21**: hold a MIDI key across a loop
wrap during recording — the wrap correctly finalizes the in-flight curve,
but the held note then goes silent in the recording on the loop-in side.
The synth audio actually keeps playing (it's tied to noteOff, not to the
recording lifecycle) so the user *thinks* recording is fine, but the next
release produces nothing.

The exploration narrowed it to one line. Compare:

[src/main.ts:2441](src/main.ts:2441) — `finalizeMidiVoice` removes the
planchette after finalizing the buffer:

```ts
function finalizeMidiVoice(midiNote: number) {
  // ...
  const curve = composeEngine.finalizeCurve(voiceId, () => history.snapshot());
  if (curve && track) {
    store.mutate(() => { track.curves.push(curve); });
  } else if (!track) {
    composeEngine.clearBuffer(voiceId);
  }
  store.removePerformPlanchette(voiceId);   // ← problem on loop wrap
  bgDirty = true;
}
```

[src/main.ts:2470](src/main.ts:2470) — `finalizeComposeRecordedCurves` (the
LMB-held perform reference, which the backlog explicitly says to match)
finalizes the buffer **without** removing the planchette:

```ts
for (const voiceId of voiceIds) {
  const curve = composeEngine.finalizeCurve(voiceId, () => history.snapshot());
  if (curve) finalized.push({ voiceId, curve });
}
// ...store.mutate({ track.curves.push(curve); ... }) — no removePerformPlanchette
```

`captureComposeRecordingSample` ([src/main.ts:2414](src/main.ts:2414))
gates per-voice capture on the presence of the planchette, and
`composeEngine.finalizeCurve` clears the buffer rather than deleting it
([src/canvas/performance-engine.ts:119](src/canvas/performance-engine.ts:119)).
So **if we leave the planchette in place after the wrap-time finalize, the
next capture frame writes into a fresh buffer under the same voiceId** and
the held key naturally continues recording — same way LMB does.

## Approach

Single-call-site fix: keep the planchette across the wrap finalize for MIDI
voices, identically to how LMB perform already keeps it.

Two-line change in spirit:
1. Give `finalizeMidiVoice` an optional `keepPlanchette` flag.
2. Pass `true` from the loop-wrap path; everywhere else keeps today's
   behaviour (planchette removed on noteOff / stop / AFK / disarm).

`finalizeAllInFlightMidiVoices` becomes a thin wrapper that forwards the
option.

The synth's audio side needs no changes — it's driven by the noteOn /
noteOff callbacks ([src/main.ts:846](src/main.ts:846), [:854](src/main.ts:854))
which are independent of the planchette / capture path. A held key emits
no noteOff at the wrap, so the OscillatorNodes keep running.

## Implementation

### 1. `finalizeMidiVoice` — add `keepPlanchette` opt

[src/main.ts:2441](src/main.ts:2441)–[src/main.ts:2456](src/main.ts:2456):

```ts
function finalizeMidiVoice(
  midiNote: number,
  opts: { keepPlanchette?: boolean } = {},
) {
  const voiceId = `midi-${midiNote}`;
  const st = store.getState();
  const planchettePresent = st.performance.planchettes.some(p => p.voiceId === voiceId);
  if (!planchettePresent) return;
  const trackId = st.midiArmedTrackId;
  const track = trackId ? st.composition.tracks.find(t => t.id === trackId) : null;
  const curve = composeEngine.finalizeCurve(voiceId, () => history.snapshot());
  if (curve && track) {
    store.mutate(() => { track.curves.push(curve); });
  } else if (!track) {
    composeEngine.clearBuffer(voiceId);
  }
  if (!opts.keepPlanchette) {
    store.removePerformPlanchette(voiceId);
  }
  bgDirty = true;
}
```

### 2. `finalizeAllInFlightMidiVoices` — forward the opt

[src/main.ts:2460](src/main.ts:2460)–[src/main.ts:2468](src/main.ts:2468):

```ts
function finalizeAllInFlightMidiVoices(opts: { keepPlanchette?: boolean } = {}) {
  const notes: number[] = [];
  for (const p of store.getState().performance.planchettes) {
    if (!p.voiceId.startsWith('midi-')) continue;
    const n = Number(p.voiceId.slice('midi-'.length));
    if (Number.isFinite(n)) notes.push(n);
  }
  for (const n of notes) finalizeMidiVoice(n, opts);
}
```

### 3. `onLoopWrap` callback — pass `keepPlanchette: true`

[src/main.ts:2544](src/main.ts:2544)–[src/main.ts:2549](src/main.ts:2549):

```ts
onLoopWrap: () => {
  if (g.recordArmed && composeEngine.isLmbDown()) finalizeComposeRecordedCurves();
  // Held MIDI notes split at the wrap into separate curves but keep their
  // planchettes so capture continues under the same voiceId on the loop-in
  // side. Matches LMB-held perform behaviour. (BACKLOG 8.21)
  finalizeAllInFlightMidiVoices({ keepPlanchette: true });
},
```

## Edge cases

| Case | Behaviour after fix |
|---|---|
| Hold one note across one wrap, release after | Curve A: noteOn → wrap. Curve B: wrap → release. ✓ |
| Hold across multiple wraps | One curve per loop pass, plus the final release segment. ✓ |
| Release exactly at the wrap (within a few ms) | Wrap finalizes (keeps planchette). NoteOff finalizes the just-cleared buffer (likely <2 samples, returns null), removes planchette. No phantom curve. ✓ |
| User disarms MIDI during a held note across wrap | `finalizeAllInFlightMidiVoices()` (default removeplanchette=true at the disarm site) cleans up properly. ✓ |
| Multiple held notes, wrap fires | All planchettes preserved; each gets its own loop-in→… continuation curve. Same as LMB multi-voice today. ✓ |
| Loop wrap when no MIDI key is held | No planchettes to iterate. No-op. ✓ |
| `setPerformCurrentCurve` (LMB calls it post-finalize, MIDI doesn't) | Pre-existing asymmetry, **out of scope** for this fix — MIDI recording already works without it for non-wrap cases. If the live-recording-trail (BACKLOG 8.18) glitches for MIDI in this exact wrap-handoff frame, file a follow-up. |
