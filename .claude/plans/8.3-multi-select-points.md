# BACKLOG 8.3 — Multi-select points: shift-click + drag-marquee

## Context

The Select tool today supports shift+click to multi-select whole curves, but point selection is single-only (`selectedPointIndex: number | null`). For complex curves with many control points, there's no way to grab a subset of points and operate on them as a group. This is the foundation for a more expressive editing model — once we can select a set of points, drag/delete/transform-box ops can operate on point-subsets as naturally as they do on whole curves today.

Scope locked in by design Q&A:
- Shift+click on an **anchor** toggles the *individual point*; shift+click on a **segment** continues to toggle the whole curve.
- Drag-marquee on empty canvas selects **anchor points whose positions fall inside the rect** (not curves crossed by the rect).
- Operations in this PR: selection state + visual highlight, drag-translate the group, Delete, and Transform Box bounded to the selected points. Defer copy/paste, alt-drag duplicate, scissors/join interactions to a follow-up.
- **Active-track-only** (matches PR #48 / 8.23): shift-click and marquee are scoped to the active track. Cross-track plain-click still switches tracks per 8.23.

## Data model

### New AppState field (`src/types.ts:179-221`)

```ts
selectedPointKeys: Set<string>;  // "<curveId>:<idx>" keys
```

We use a `Set<string>` rather than `Set<{curveId, idx}>` so identity comparisons work without a custom equality. Helper module `src/model/point-selection.ts` (new):

```ts
export function pointKey(curveId: string, idx: number): string;
export function parsePointKey(key: string): { curveId: string; idx: number };
export function pointKeysByCurve(keys: Set<string>): Map<string, Set<number>>;
```

### Index-stability stance

Indices are not stable across point insertions/deletions, but multi-point selection is **transient UI state** — it only lives between user actions. We do not need stable point IDs. Instead:
- Mutators that delete points/curves call a new `prunePointSelection()` to drop now-invalid keys.
- Mutators that insert points clear the selection (a new point disturbs the user's mental model anyway).

### Existing `selectedPointIndex` retained

Keep `selectedPointIndex` as the **primary point** marker (the most recently-clicked point — used today to draw handles for editing). When `selectedPointKeys.size === 1` and that point is on the single selected curve, the two stay in sync. When `selectedPointKeys.size > 1`, `selectedPointIndex` is null (no single primary) and handles are not drawn.

## State mutators ([src/state/store.ts:225-283](src/state/store.ts))

Add to `store`:
- `setSelectedPointKeys(keys: Set<string>)` — replace.
- `togglePointKey(curveId: string, idx: number)` — flip membership.
- `addPointKeys(keys: Iterable<string>)` — additive (used by marquee).
- `clearPointSelection()` — empty the set + reset `selectedPointIndex`.
- `prunePointSelection(predicate: (curveId, idx) => boolean)` — drop keys failing predicate.

Update `setSelectedTrack`, `setSelectedCurve`, `setSelectedCurves` to also clear `selectedPointKeys` (selection is per-track-scope, matching the existing curve-set behavior).

## Interaction state ([src/canvas/interaction.ts:29-58](src/canvas/interaction.ts))

Extend `InteractionState`:
```ts
marquee: { startWorld: Vec2; currentWorld: Vec2; additive: boolean } | null;
pointGroupDrag: { dragStartWorld: Vec2; originalPositionsByKey: Map<string, Vec2> } | null;
```

`pointGroupDrag` is set when mouse-down hits an already-selected point in multi-point mode; on each move, every selected point's position is set to `original + (cursor - dragStart)`, applying the same shift-axis-constrain logic that the existing single-point drag uses.

## Click-handler changes ([handleSelectClick, src/canvas/interaction.ts:630-744](src/canvas/interaction.ts))

**Phase 1 (anchor hit)** — change shift behavior:
- Plain click on anchor: unchanged (single-curve, single-point selection, start drag) — also clear `selectedPointKeys` and re-seed it with the clicked point.
- **Shift+click on anchor**: toggle that point in `selectedPointKeys`. If the parent curve isn't already in `selectedCurveIds`, add it (so the curve renders selected). After toggle, recompute transform box from the union of selected points.

**Phase 3 (segment hit)** — unchanged: shift+click toggles the whole curve.

**Phase 4 (empty-canvas miss)** — currently clears selection on plain click. New behavior: do **not** clear here. The mousedown handler will start a marquee; the marquee's `mouseup` decides whether to clear (empty marquee = small drag = clear) or commit a selection.

## Marquee ([mousedown, src/canvas/interaction.ts:275-411](src/canvas/interaction.ts))

When `activeTool === 'select'`, no transform-box hit, no curve hit, no anchor hit — and the existing `handleSelectClick` would have hit Phase 4 (empty canvas) — start a marquee instead:

```ts
istate.marquee = { startWorld: rawPt, currentWorld: rawPt, additive: e.shiftKey };
// don't clear selection yet — wait for mouseup
```

**On `mousemove` ([src/canvas/interaction.ts:120](src/canvas/interaction.ts))**: if `istate.marquee`, update `currentWorld` and request a redraw. Set cursor to `crosshair`.

**On `mouseup` ([src/canvas/interaction.ts:413](src/canvas/interaction.ts))**: finalize:
1. Compute axis-aligned rect in world space from `(startWorld, currentWorld)`.
2. If the rect's screen size is < 4×4 px (a click, not a drag): treat as plain click on empty canvas → clear selection if not shift.
3. Otherwise, walk the **active track's** curves, collect every anchor whose `position` falls inside the rect, and:
   - If `additive` (shift held): `addPointKeys(...)`.
   - Else: `setSelectedPointKeys(...)`.
4. Sync `selectedCurveIds` to the union of parent-curve IDs.
5. Rebuild the transform box.

Refactor `handleSelectClick` so the empty-canvas branch returns a sentinel ("no hit") and the mousedown handler initiates the marquee on that sentinel.

## Group drag

Mouse-down on a point that's already in `selectedPointKeys` and selection size ≥ 2: instead of replacing selection with a single-point drag, start `pointGroupDrag`:

```ts
istate.pointGroupDrag = {
  dragStartWorld: pt.position,
  originalPositionsByKey: snapshotEverySelectedPointPosition(),
};
history.snapshot();
```

In `handleDrag` (the existing dispatch from `mousemove`'s `if (istate.dragging)` branch — see [src/canvas/interaction.ts:270-272](src/canvas/interaction.ts)), add a new branch when `istate.pointGroupDrag` is set:

```ts
const dx = eff.wx - istate.pointGroupDrag.dragStartWorld.x;
const dy = eff.wy - istate.pointGroupDrag.dragStartWorld.y;
store.mutate(() => {
  for (const [key, orig] of istate.pointGroupDrag.originalPositionsByKey) {
    const { curveId, idx } = parsePointKey(key);
    const curve = findCurve(curveId);
    if (curve && curve.points[idx]) {
      curve.points[idx].position.x = orig.x + dx;
      curve.points[idx].position.y = orig.y + dy;
    }
  }
});
```

Reuse `movePoint` (in [src/model/curve.ts](src/model/curve.ts)) where it handles handle-clamping after a position change — or call `reclampHandlesAround` per affected point. **Important:** After moving, points within a single curve must remain **sorted by X** (curves require monotonic X). If a group-drag would cause a sort-order violation (i.e. one selected point passes a non-selected neighbor), clamp dx to the maximum delta that preserves order. This is an edge case worth handling explicitly — without it, drag can corrupt curve geometry.

Snap behavior: respect the same snap-grid the existing single-point drag uses, but apply snap to the cursor delta, not per-point (otherwise points drift relative to each other).

Mouse-up: clear `istate.pointGroupDrag`.

## Delete

Find the Delete keybinding handler in [src/main.ts](src/main.ts). New branch:

```ts
if (state.selectedPointKeys.size > 0) {
  history.snapshot();
  // Group keys by curve, sort indices descending (so splice doesn't shift earlier indices).
  const byCurve = pointKeysByCurve(state.selectedPointKeys);
  store.mutate(() => {
    for (const [curveId, indices] of byCurve) {
      const curve = findCurve(curveId);
      if (!curve) continue;
      const sorted = [...indices].sort((a, b) => b - a);
      for (const idx of sorted) {
        curve.points.splice(idx, 1);
      }
      // If curve drops below 2 points, remove the curve entirely (a 0- or 1-point
      // curve is degenerate and won't render a segment).
      if (curve.points.length < 2) {
        removeCurveFromTrack(curveId);
      } else {
        // Re-clamp neighbor handles around the deletion gaps.
        applyAutoSmoothHandles(curve);  // or reclampHandlesAround at each gap
      }
    }
  });
  store.clearPointSelection();
  rebuildTransformBox(...);
  return;
}
// else: existing whole-curve delete behavior
```

Decision: **deleting all points of a curve also deletes the curve.** Alternative would be to refuse the delete or leave a degenerate curve, both worse UX.

## Transform Box adaptation

Today `TransformBoxState.curveIds` + `originalPointsMap` assume whole-curve transforms. For multi-point mode, extend:

```ts
interface TransformBoxState {
  curveIds: string[];
  originalPointsMap: Map<string, ControlPoint[]>;
  bbox: BoundingBox;
  activeHandle: TransformHandle | null;
  dragStart: Vec2 | null;
  // NEW: when set, transforms only apply to these point indices per curve.
  // null/empty means "all points of all curveIds" (existing behavior).
  pointIndicesPerCurve: Map<string, Set<number>> | null;
}
```

### `rebuildTransformBox` ([src/canvas/interaction.ts:748-775](src/canvas/interaction.ts))

When `selectedPointKeys.size > 0`:
1. Group keys by curve.
2. Compute bbox from the union of those *specific* point positions (not full curves).
3. Set `pointIndicesPerCurve` to the grouping.

Add a helper in [src/model/curve.ts:374](src/model/curve.ts):

```ts
export function computePointSubsetBBox(
  curves: BezierCurve[],
  pointIndicesPerCurve: Map<string, Set<number>>,
): BoundingBox
```

When `selectedPointKeys.size === 0`, behavior is unchanged — bbox is computed from full curves via `computeMultiCurveBBox`.

### `applyTransformToCurve` ([src/model/curve.ts](src/model/curve.ts))

Add an optional `pointIndices?: Set<number>` parameter. When provided, the function only mutates the listed indices; otherwise all points (existing behavior).

Then in the [mousemove transform-drag block (interaction.ts:236-244)](src/canvas/interaction.ts):

```ts
applyTransformToCurve(
  curve,
  origPts,
  tb.bbox,
  tb.activeHandle!,
  tb.dragStart!,
  { x: eff.wx, y: eff.wy },
  tb.pointIndicesPerCurve?.get(curve.id),  // new arg
);
```

The octave-up/down branches at [interaction.ts:352-367](src/canvas/interaction.ts) similarly need to filter by point indices when in point-mode.

## Verification

End-to-end manual test in dev server (`npm run dev` → port 5187):

1. **Shift+click point toggle**
   - Draw a curve with 4 points. Switch to Select. Shift+click anchor #1 → highlighted, curve highlighted, transform box wraps just that point.
   - Shift+click anchor #3 → both highlighted, transform box wraps both.
   - Shift+click anchor #1 again → deselected, transform box wraps just #3.

2. **Shift+click segment still toggles curve**
   - Two curves on the active track. Shift+click on the line between two anchors of curve A → whole curve A selected (existing behavior preserved). Shift+click on the line of curve B → both whole curves selected.

3. **Drag-marquee**
   - Drag a rect on empty canvas around 3 anchor points → those 3 are selected, transform box wraps them.
   - Shift+drag a rect around an additional point → previous selection persists, new point added.
   - Click (no drag) on empty canvas → clears selection. (Marquee should treat <4px drag as a click.)
   - Verify marquee only picks up active-track points; non-active-track curves stay unselected even if their points fall inside the rect.

4. **Group drag**
   - Marquee-select 3 points across 2 curves on the active track. Mouse-down on one of them and drag → all 3 move with consistent offset. Other points on both curves stay put.
   - Shift+drag → axis-constrained.
   - Drag a point past a non-selected neighbor in the same curve → drag should clamp to preserve X-monotonic order.
   - Undo (Ctrl+Z) → restores all positions.

5. **Delete**
   - Multi-select 2 points on a 4-point curve. Press Delete → just those 2 points removed, curve still has 2 remaining; geometry looks reasonable (handles re-clamped).
   - Multi-select all 4 points of a curve. Press Delete → curve disappears entirely.
   - Multi-select 1 point each from 2 different curves. Press Delete → one point removed from each.
   - Selection cleared after delete.

6. **Transform Box on subset**
   - Multi-select 3 points spanning the middle of a 6-point curve. Drag the right scale handle → only those 3 points scale; first and last don't move.
   - Octave-up arrow → only selected points shift +12 semis.

7. **Selection invariant under operations**
   - Select 3 points; switch tracks → selection clears (matches existing curve-selection behavior).
   - Select 3 points on curve A; delete curve A via right-click/menu → selection cleared.
   - Select 3 points; press Escape (if mapped) → selection cleared.

8. **No regressions**
   - Plain-click on a point still selects single-curve + single-point and starts drag (existing path).
   - Plain-click on a segment still selects whole curve.
   - Shift+click on the body of an unselected curve (segment hit) still toggles curve (Phase 3 unchanged).
   - 8.23 cross-track plain-click still switches tracks.
   - Transform box on full-curve multi-selection (no points selected) still works as before.
