# 8.18 Live recording trail visualization

> Filename note: this plan was created at the user-level default path. Per the repo
> convention (memory: "Backlog and planning docs live in the repo"), move it to
> `<repo>/.claude/plans/8.18-live-recording-trail.md` before committing the
> implementation, in the same PR that ships the work.

## Context

When the user is recording (LMB-held perform with record armed, or MIDI input),
the captured curve doesn't appear until the gesture finishes — `finalizeCurve`
RDP-simplifies the buffered samples into a `BezierCurve` only on LMB release
or MIDI note-off. During the gesture the only feedback is the planchette
position; there's nothing showing that samples are actually being captured or
where the user has been. On long curves this makes recording feel unmoored.

Goal: render a live polyline behind the planchette for each in-flight voice
during recording, sourced from the raw samples already in the engine's
recording buffer. The trail vanishes the same frame the simplified curve is
committed — no new state, no copy of the data.

## Approach

The data already exists. `PerformanceEngine.recordingBuffers` is a
`Map<VoiceId, RecordedSample[]>` populated every frame by
`captureComposeRecordingSample` ([src/main.ts:2235-2258](src/main.ts:2235)) and
cleared by `finalizeCurve` ([src/canvas/performance-engine.ts:109-121](src/canvas/performance-engine.ts:109)).
Samples are `{ beat, note, volume }`, monotonic in beat, and bounded by
`recordingBufferMax`. The render loop just needs read access.

### Critical files

- [src/canvas/performance-engine.ts](src/canvas/performance-engine.ts) — add a read-only accessor.
- [src/canvas/planchette.ts](src/canvas/planchette.ts) — add `renderRecordingTrails`. Reuse `prismPlanchetteStroke` for voice colors but resolve to a non-gradient stroke (gradients are anchored to the circle glyph and don't make sense on a long polyline).
- [src/main.ts](src/main.ts) — call the renderer just before the rail/planchette block (~line 2855).
- [help.html](help.html) — note the live trail in the recording section.

### Engine: expose buffers read-only

Add to the `PerformanceEngine` interface and `createPerformanceEngine` impl in
[src/canvas/performance-engine.ts](src/canvas/performance-engine.ts):

```ts
getRecordingBuffers(): ReadonlyMap<VoiceId, readonly RecordedSample[]>;
```

Implementation just returns the existing private `recordingBuffers` map typed
as `ReadonlyMap`. No copy — the renderer iterates and reads, doesn't mutate.

### Renderer: `renderRecordingTrails`

New function in [src/canvas/planchette.ts](src/canvas/planchette.ts) (co-located
with the other rail/planchette renderers — same file, same draw context, shares
the Prism color helpers):

```ts
export function renderRecordingTrails(
  ctx: CanvasRenderingContext2D,
  vp: Viewport,
  buffers: ReadonlyMap<string, readonly RecordedSample[]>,
  prismMode: boolean,
): void
```

For each voice with ≥ 2 samples:
- Resolve a solid stroke color: in Prism mode, primary → middle rainbow stop
  (gradient won't work on a long polyline; pick a single representative stop),
  `harmony-N` → `PRISM_RAINBOW_STOPS[N]`. Non-Prism / MIDI / fallback →
  `PRIMARY_COLOR`. Factor a small helper `recordingTrailColor(voiceId, prismMode)`
  in the same file that mirrors `prismPlanchetteStroke` but returns a string.
- Stroke a polyline of `vp.worldToScreen(beat, note)` for every sample.
- `lineWidth: 2`, `globalAlpha: 0.7`, `lineCap: 'round'`, `lineJoin: 'round'`.
- Clip Y to the canvas body (above ruler, below bottom edge) — same gate as `renderPlanchettes`.

Why polyline (not breadcrumb-with-fade): the buffer is already capped at
`recordingBufferMax` and samples are dense (one per animation frame), so a
plain polyline both shows the full captured path and fades naturally when the
oldest samples roll off the buffer cap. The backlog item says raw samples are
the preferred form "if practical" — they are.

### Wire into the render loop

In `render()` in [src/main.ts:2618-2939](src/main.ts:2618), insert the call
between the snap guides block (line 2852) and the rail/playhead block
(line 2855):

```ts
renderRecordingTrails(
  fgCtx,
  viewport,
  composeEngine.getRecordingBuffers(),
  state.harmonicPrism.drawMode,
);
```

This places the trail above committed curves and snap guides, but below the
rail/planchette glyph and the metronome flash — so the planchette visually
"leads" the trail like a pen tip. World coordinates via `vp.worldToScreen`
mean Scroll Canvas mode is automatically handled (the trail anchors to beats,
canvas pans under it).

No conditional gating needed: when nothing is being recorded the buffers are
empty and the function early-outs per voice. `recordingBuffers` is also
cleared by `stopSession` ([src/canvas/performance-engine.ts:93-98](src/canvas/performance-engine.ts:93))
and on every `finalizeCurve`, so the trail disappears the same frame the
simplified curve appears — seamless handoff.

### Lifecycle correctness (no extra code needed)

- **LMB release** → `finalizeComposeRecordedCurves` calls `finalizeCurve` per voice → buffers cleared → trail clears, simplified curve renders.
- **MIDI note-off** → `finalizeMidiVoice` clears that voice's buffer → that trail disappears, others continue.
- **Loop wrap (MIDI)** → `finalizeAllInFlightMidiVoices` clears all MIDI buffers; held notes restart fresh on the wrap (currently broken per backlog 8.21, but our trail correctness doesn't depend on that fix).
- **AFK auto-stop** → engine `stopSession` clears all buffers → trails clear.
- **Not armed** → `captureComposeRecordingSample` doesn't push samples → buffers stay empty → no trail. Correct: trail represents capture, not perform.

## Verification

Dev server: `npm run dev` (port 5187 for this worktree).

Manual cases:
1. **Single LMB record** — arm record, hold LMB, draw a curve. Polyline trails the planchette while held. On release, trail vanishes and the simplified Bezier appears in its place with no visual gap.
2. **Harmonic Prism Draw + LMB record** — toggle Prism Draw, arm, hold LMB. N colored trails (primary + rainbow harmonies) all visible. All clear on release; N grouped curves commit.
3. **MIDI input recording** — arm MIDI track, hold a key, then a second. Two trails colored as PRIMARY. Note-off on one clears just that trail.
4. **Scroll Canvas ON during long recording** — the trail anchors to beats and scrolls left as the canvas pans; the planchette stays at the rail.
5. **Scroll Canvas OFF + record** — recording forces `effectiveScrollCanvas` true, so the visual is the same as case 4.
6. **AFK auto-stop** — arm record, leave alone past `afkTimeoutMs`. Trail clears when the engine auto-stops.
7. **Loop wrap (LMB)** — record across the loop end; the in-flight curve finalizes, trail clears, and a new trail begins at the loop start as the next gesture continues.
8. **Performance** — record a long curve to confirm the trail stays smooth at 60fps under the existing `recordingBufferMax` cap.

Out of scope:
- No fading/opacity gradient on the trail. Buffer cap already gives a natural maximum length.
- No new app-state, no localStorage persistence — the trail is purely derived from engine state.
- 8.21 (MIDI sustained note across loop wrap) is a separate bug; this plan doesn't depend on or fix it.
