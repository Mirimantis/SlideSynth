# 10.5 Deliberate "Record Next Full Pass" — Build Plan

Build plan for BACKLOG 10.5 (Phase 10, [performance-jam-looper-plan.md](../../performance-jam-looper-plan.md)). The structured counterpart to 10.2's retrospective keep: **keep** rescues serendipitous leads after the fact, **record next pass** places drones and harmony beds precisely.

## Goal

Arm it, and exactly one full loop pass is recorded — starting at the loop point, auto-committing and disarming at the next one.

## Decisions (settled 2026-07-30)

- **Loop off → auto-enable Loop**, with a 2-second toast reading exactly `Record next Pass: Loop On`, so the transport change is never silent.
- **Trigger: `Shift+R`, and `Shift`+click on the Record button.** Reads as "record, but scheduled", keeps one obvious place to look, and gives mouse users the same affordance. The Record button gains a third **queued** state, visually distinct from armed and recording.
- **From idle: start the loop and record its first pass.** Playback begins at the loop-in point and recording is live immediately — that first cycle *is* the full pass. One action from stopped to a recorded layer.
- **Armed mid-pass: recording begins at the next loop point.** Always queued, never partial, so you always know which cycle you're recording.
- **Cancel** by pressing again in either state; anything already captured commits rather than being thrown away (matching how stopping a normal recording behaves).

## Bug found while tracing this (fixed here)

At a loop wrap, `onLoopWrap` currently resets the layer boundary **before** committing wrap-time material:

```
closeLmbPhrases();
currentLayerTrackId = null;      // ← boundary reset
if (recordArmed && isLmbDown()) finalizeComposeRecordedCurves();
```

So a gesture held across the seam has its **pre-wrap half committed into the next pass's layer**, and anything kept during that next pass joins it — breaking "one pass = one layer" for held gestures. 10.5 depends on wrap-time commits landing in the right layer, so the reset moves **after** the commits.

## Implementation

### 1. State

- `PassRecordState = 'off' | 'queued' | 'recording'` in [src/types.ts](../../src/types.ts), on `PerformanceState` as `passRecordState`. Runtime only, never persisted.
- `store.setPassRecordState`.

### 2. Arming (`toggleRecordNextPass`)

1. Already `queued` or `recording` → cancel: commit anything in flight, disarm, back to `off`, toast.
2. Requires a selected track (same guard as `R`).
3. Loop off → `playback.setLoop(true)`, sync the loop checkbox, toast `Record next Pass: Loop On`.
4. Transport stopped → start playback at `loopStartBeats` over the loop range, `setPerformArmed(true)`, state `recording` (this first cycle is the pass), plus the usual session setup: `setPerformPhase('playing')`, `composeEngine.startSession`, `resetLayerSession`, `updatePlayState`, viewport snap.
5. Transport running → state `queued`; recording starts at the next wrap.

### 3. The wrap state machine

In `onLoopWrap` ([src/main.ts](../../src/main.ts)), after the existing seal-and-commit steps and **before** the layer-boundary reset:

- `recording` → the pass just finished: `setPerformArmed(false)`, state `off`, toast. Transport keeps looping so the new layer is immediately audible.
- `queued` → the pass just started: `setPerformArmed(true)`, state `recording`.

### 4. UI

- `Shift+R` in the keydown handler; `Shift`+click on `btn-record` routed to the same function.
- `updateRecordButtonVisuals` adds a `queued` class; `.record-btn.queued` styled amber and pulsing in [styles/main.css](../../styles/main.css), distinct from armed (red pulse) and recording (solid red).
- `effectiveScrollCanvas()` treats a non-`off` pass-record state as scrolling, so the view doesn't jump modes at the wrap.
- [help.html](../../help.html): the two capture styles side by side, the auto-Loop behaviour, cancel, and that it lands on its own layer when Layer mode is on.

## Tests & verification

**Unit:** the wrap transition is a pure state step — extract `nextPassRecordState(current)` into [src/model/layer.ts](../../src/model/layer.ts)'s neighbourhood (or a small module) and test `queued → recording → off`, plus that `off` stays `off`.

**Full suite:** `npx tsc --noEmit` + `npx vitest run` green; golden format test untouched (state is runtime-only).

**Manual (dev server, port 5187):**
1. Loop off + `Shift+R` → Loop switches on, toast reads `Record next Pass: Loop On`.
2. From idle → playback starts at loop-in and records that first pass; at the wrap it commits and disarms.
3. Armed mid-pass → Record button shows queued, recording starts at the wrap, ends at the next.
4. With Layer mode on, the pass lands on its own layer (and a gesture held across the seam no longer leaks into the next pass's layer — the bug fix).
5. `Shift+R` again while queued cancels; while recording it commits what exists and disarms.
6. Plain `R` still behaves exactly as before.

## Out of scope

Multi-pass overdub (plain `R` covers open-ended recording), count-in before a queued pass, and 10.6's live loop taps — deferred at the user's request.
