# 10.3 Layer-Per-Pass Looping — Build Plan

Dedicated build plan for BACKLOG 10.3 (Phase 10, [performance-jam-looper-plan.md](../../performance-jam-looper-plan.md)). Follows 10.1 (jam clock) and 10.2 (retrospective capture), which already commit curves through a single shared choke point.

## Goal

Turn capture into actual **looping**: each pass you perform becomes its own track, so passes stack into a choir instead of piling onto one track. Layers are tracks, so they inherit mute / solo / volume and per-layer tone for free from the existing track panel.

## Decisions (settled 2026-07-29)

- **Trigger: a `Layer` toggle in the transport, default off.** Off keeps today's behavior exactly (commits land on the selected track), so ordinary editing and armed recording onto a chosen track are unchanged. On = looper mode. Persisted to localStorage like the Lock Rail toggle.
- **Boundary: the loop wrap.** The first commit after a wrap *opens* a layer; every later commit in that same pass joins it. This keeps the two halves of a line held across the seam together, because both `K` presses happen in the same pass (see 10.2). With Loop off there are no wraps, so a session is one layer.
- **Layers are created lazily, on commit** — never on the wrap itself. A pass where you play nothing leaves no empty track behind.
- **Active track stays on the source.** The track you started from remains active, so every layer inherits the same tone and you keep performing "from" one instrument across many passes. (Note this differs from 8.2's `moveCurvesToNewTrack`, which follows selection to the new track.)
- **Visual distinguishability: dimming only for now.** Layers inherit the source tone, so they share its color; 8.23's non-active-track dimming plus the track panel list is the affordance. **Watch-item:** because the active track is the (now empty) source, everything you build renders dimmed while the one bright track is blank. If that reads poorly, the follow-up is an optional `Track.color` auto-assigned from a palette — purely additive to the schema, so no migration or `formatVersion` bump. Not built in this pass.
- **Ceiling: 16 tracks total** (MPE / VCV poly-cable parity from the plan doc). At the cap, stop opening layers, keep committing to the most recent one, and toast once.
- **Scope: LMB-perform and keep commits only.** MIDI-armed recording keeps its explicit armed-track routing — arming a track is already a deliberate "put it here," and letting two different source tracks feed one shared layer would mean one tone silently wins. Noted as out of scope below.

## Implementation

### 1. Layer helpers (new, unit-testable)

New `src/model/layer.ts`, peeling logic out of `main.ts` per the backlog's standing note:

- `LAYER_TRACK_LIMIT = 16`
- `nextLayerName(tracks: Track[]): string` — `Layer N`, where N is one past the highest existing `Layer <n>` so deleting a layer doesn't cause duplicate names.
- `createLayerTrack(source: Track, tracks: Track[]): Track` — `createTrack(nextLayerName(tracks), source.toneId)` with `volume` copied from the source; mute/solo default false.
- `canOpenLayer(tracks: Track[]): boolean` — `tracks.length < LAYER_TRACK_LIMIT`.

### 2. State

- `layerModeEnabled: boolean` on `AppState` + `setLayerMode` mutator, persisted to localStorage following the Lock Rail / `scrollCanvasEnabled` pattern.
- `currentLayerTrackId: string | null` — a module-level session variable in main.ts (runtime only, never persisted, like the magnetic clock accumulator). Cleared on loop wrap, on session start, and in `composePerformStop`.

### 3. Routing

One new resolver, called from inside `commitFinalizedCurves` so both commit paths inherit it with no duplication:

```
resolveCommitTrack(source: Track): Track
  if !layerModeEnabled            → source                    (today's behavior)
  if currentLayerTrackId is live  → that track                 (join this pass's layer)
  if !canOpenLayer(tracks)        → last layer + one-shot toast (at the 16-track cap)
  else                            → createLayerTrack(source), push, set currentLayerTrackId
```

Ordering matters for undo: layer creation must happen *after* the `history.snapshot()` both callers already take, so creating the track and committing its curves collapse into one undo entry — consistent with the 10.4 decision that one kept pass is one undo step. Since `commitFinalizedCurves` runs after the snapshot in both paths, hooking it there is automatically correct.

`store.setPerformCurrentCurve(voiceId, curve.id)` stays as-is; the active track is deliberately *not* changed (decision above), so no `setSelectedTrack` call.

### 4. Loop wrap

In the existing `onLoopWrap` handler, alongside `closeLmbPhrases()`: clear `currentLayerTrackId` so the next commit opens a fresh layer. That single line is the whole "one pass = one layer" rule.

### 5. UI

- `Layer` toggle switch in the transport row beside Loop, wired to `setLayerMode`, mirrored back from the store like the other toggles. Tooltip explains "each loop pass becomes its own track."
- The track panel needs no change — it is already the layer list, with per-layer mute/solo/tone/volume.
- [help.html](../../help.html): document Layer mode, the one-pass-one-layer rule, the 16-track cap, and that MIDI-armed recording ignores layering. Same PR, per the housekeeping rule.

## Tests & verification

**Unit — new `src/model/layer.test.ts`:**
- `nextLayerName` on an empty comp, alongside non-layer tracks, with gaps after a deletion, and against names like `Layer 12`.
- `createLayerTrack` inherits `toneId` + `volume`, resets mute/solo, generates a distinct id.
- `canOpenLayer` boundary at exactly 16.

**Full suite:** `npx tsc --noEmit` + `npx vitest run` green. `layerModeEnabled` is localStorage-only and `currentLayerTrackId` is runtime-only, so the golden format test should be untouched — if it moves, something is leaking into the saved file.

**Manual (dev server, port 5187):**
1. Layer off → keep and armed record still land on the selected track (regression).
2. Layer on, Loop on, jam: keep a phrase on three successive passes → three tracks `Layer 1..3`, each holding that pass's curve, source track still active and empty.
3. Two keeps within one pass (including the loop-seam double-press from 10.2) → both land on the *same* layer.
4. A pass where nothing is played leaves no empty track.
5. Mute/solo individual layers mid-jam; confirm the choir thins out and each layer is independently audible.
6. A fresh layer sounds on the pass it appears on, not a pass later (relies on 10.2's `adoptNewCurves`).
7. Undo after a keep removes the curve *and* its newly created layer in one step.
8. Fill to 16 tracks → layering stops, toast appears once, further keeps land on the last layer.
9. Layer off mid-session → next commit returns to the selected track.

## Out of scope

MIDI-armed recording layering (explicit armed-track routing wins), per-track color (the watch-item above — revisit after testing), reordering/renaming layers beyond what the track panel already does, layer freeze/bounce, the undo-last-layer key (10.4 — it will target the most recent kept pass, which this item makes a whole track), and per-layer dynamics (11.x).
