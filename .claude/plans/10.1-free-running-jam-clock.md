# 10.1 Free-Running Jam Clock — Build Plan

Dedicated build plan for BACKLOG 10.1 (first slice of [performance-jam-looper-plan.md](../../performance-jam-looper-plan.md)).

## Goal

Formalize **jam mode**: a dedicated transport control starts a free-running clock — canvas scrolls under the rail, LMB perform sounds tones, magnetic snap fully live, **nothing armed**, no fixed end. This is the foundation 10.2 (retrospective capture) and the rest of Phase 10 build on.

## Decisions (settled 2026-07-19)

- **Entry:** dedicated Jam toggle in Transport + plain `J` hotkey (`Ctrl+J` is taken; plain `J` is free). Classic Play keeps its stop-at-end semantics.
- **Tempo:** composition BPM, as-is. (BPM edits mid-jam retempo on next clock start, matching current playback behavior — live retempo is out of scope.)
- **No countdown** on jam start — countdown exists to prep a recording; jam starts instantly.
- **Idle timeout (un-armed jam):** long — 10 min of no input auto-stops the clock, reusing the existing AFK warning popup. Armed recording keeps its existing 2-min AFK unchanged.
- **Magnetic scope:** physics engages in **all perform contexts** (perform planchette live — hovering or sounding, transport running or not). Edit tools (draw/select) keep instant snap.
- **Beat-snap:** no code change needed — X-snap already never applies to perform capture (comment at [src/main.ts:2414](../../src/main.ts)). The "jam beat-snap defaults off" decision lands as a quantize-on-keep option in 10.2, not here.
- **Hard ceiling:** `MAX_CANVAS_EXTENT` (10,000 beats ≈ 83 min @ 120 BPM) stays as the safety stop for the "endless" clock.

## Implementation

### 1. Jam state + transport UI

- `types.ts` / `store.ts`: add `jamActive: boolean` to the `performance` slice (runtime-only — **not** persisted to the composition) + `setJamActive` mutator.
- `index.html` + [src/main.ts](../../src/main.ts): new `btn-jam` toggle in Transport (near Record); plain `J` hotkey in the main keydown handler (respect the existing input-focus guard). `styles/main.css`: active/jamming visual state.
- **Start** (`jamStart()`): `ensureResumed()`; start from the beat under the rail (same rail-beat logic as `startComposePerformPlayback`); honor Loop if enabled (play the loop range, wraps fire); otherwise open-ended (below). Set `jamActive`, `setPlaybackState('playing')`, `setPerformPhase('playing')` (so loop-wrap detection + planchette flash work), `composeEngine.startSession(...)`, `updatePlayState(true)`, snap viewport to beat.
- **Stop:** toggling Jam off, Stop button, and idle timeout all route through `composePerformStop()` (already finalizes/no-ops safely when unarmed) + clear `jamActive`. Audit `composePerformStop` to clear the flag centrally.
- `effectiveScrollCanvas()` returns true while `jamActive` too (jam always scrolls, like recording).
- **Record interplay:** while jamming, Record uses the existing "playback already running → arm immediately" path. Keep the current "record-toggle while recording = full stop" behavior for now — disarm-back-to-jam is looper UX, revisit in 10.3/10.5 (note added there when built).

### 2. Open-ended play range (kill the +10,000 hack)

- New constant `OPEN_END_BEAT = MAX_CANVAS_EXTENT` in [src/constants.ts](../../src/constants.ts) (same file as `MAX_CANVAS_EXTENT`, keeps the invariant visible).
- Jam (loop off): `playback.play(comp, startBeat, OPEN_END_BEAT)`. Replace both `+ 10_000` sites with `OPEN_END_BEAT` so jam and armed recording share semantics. Hitting the ceiling stops cleanly via the existing end-of-range path.
- **No playback-engine changes needed** — a finite far end reuses the engine as-is, and the empty-composition guard is already bypassed when `endBeat` is passed.

### 3. Idle timeout for un-armed jam

- New constant `JAM_IDLE_TIMEOUT_MS = 600_000` (10 min).
- [src/canvas/performance-engine.ts](../../src/canvas/performance-engine.ts): generalize the AFK check — `TickArgs` gains `idleTimeoutMs` (caller passes `afkTimeoutMs` when armed, `JAM_IDLE_TIMEOUT_MS` when un-armed jam, `Infinity`/skip otherwise) and `tick` fires `onAfkTimeout` when `now - lastActivityAt > idleTimeoutMs`. Replace `getAfkTimeoutMs()` with the effective-timeout value (or add a parameter) so the warning popup countdown stays accurate in both modes.
- Activity marks: un-armed jam has no `captureSample` marks, so mark activity on perform-context pointer movement (`composeUpdatePlanchette` / the perform mousemove path) and LMB, so a noodling user never sees the popup.
- `tickComposePerform` in [src/main.ts](../../src/main.ts): keep the existing 8.20 suppression logic for armed recording untouched; add the un-armed-jam branch selecting `JAM_IDLE_TIMEOUT_MS`.

### 4. Magnetic snap: real time base + perform-context scope

- **Time base — one clock, no source switching:** physics only needs *dt*, and wall-clock dt equals playback dt (both real time). Maintain a module-level monotonic accumulator in [src/main.ts](../../src/main.ts), advanced every render frame: `magneticNowBeats += (now - lastNow) / 1000 * bpm / 60`. Pass that to `updateMagnetic` instead of `playback.getPositionBeats()`. `MAX_DT_BEATS` in [src/utils/snap-magnetic.ts](../../src/utils/snap-magnetic.ts) already absorbs pauses/tab-throttle; no changes to the integrator itself.
- **Scope:** drop the `performing` (`isLmbDown()`) condition from the magnetic gate in `computeComposeCursorPitch` — keep `snapEnabled && magneticEnabled`. The function is only called from perform paths, so edit tools are unaffected. Hovering/idle-preview planchettes now settle magnetically ("gravity at rest"). Verify the None-mode null-attractor branch and the `resetMagnetic` calls on planchette leave still behave.
- `tickComposePitchMode` keeps advancing physics while the cursor is still; its `isLmbDown` branch (synth retune) is unchanged.

### 5. Docs

- [help.html](../../help.html): document Jam mode, the `J` hotkey, and the idle timeout (housekeeping rule: same PR).
