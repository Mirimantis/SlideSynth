# 10.4 Undo Last Layer / Drop Last Pass — Build Plan

Dedicated build plan for BACKLOG 10.4 (Phase 10, [performance-jam-looper-plan.md](../../performance-jam-looper-plan.md)). Depends on 10.3 (layer-per-pass), which supplies the layer track and the `created` flag this item consumes.

## Goal

The move the plan doc calls **sacred in live looping**: throw away a bad pass instantly, with one key, without leaving the performance.

## The mechanism, and why it isn't `history.undo()`

The recorded 10.4 decision was "one stack, semantic key — a targeted undo of the most recent kept pass." Reading the history implementation settles how that has to work: [src/state/history.ts](../../src/state/history.ts) is a **linear stack of whole-composition clones** (max 50) with no way to excise a middle entry. So once you've edited *after* keeping a pass, no rewind can remove just that pass — `Ctrl+Z` would take the edits instead.

So the key is a **forward delete that is itself undoable**: snapshot, then remove the most recent pass. This satisfies the decision's intent exactly — one stack, no mode-dependent undo, each pass one entry — and it behaves better than a rewind, because it works regardless of what you did in between. It also means **`Ctrl+Z` restores a dropped layer**, which is the classic looper "redo layer" for free.

## Decisions (settled 2026-07-29)

- **Scope: any performed pass** — retrospective keeps and armed-recorded passes alike. Both already commit through one choke point, so one rule covers both.
- **Empty layers: removed if that pass created them.** Dropping fully reverses the pass. A track you made yourself, or a layer you've since added other curves to, keeps its track — only the curves go.
- **Layer mode off: still drops the last pass's curves** (just no track removal), so the key stays useful for plain recording.
- **Walk-back: all passes this session**, each press taking the next-most-recent — the same idiom as repeated `K` presses walking backward through the keep buffer.
- **Key: `U`** (free; `K` = keep, `J` = jam, `R` = record). No transport button — the transport already carries play/pause/stop/record/jam/keep, and this is a live-performance action. Discoverable via help + the toast.
- **Log lifetime: the app session.** Survives jam stop (consistent with 10.2's buffer surviving Stop) and is cleared on composition load/new.

## Design: an append-only pass log

```ts
interface CommittedPass {
  trackId: string;
  curveIds: string[];
  createdTrack: boolean;   // did this pass open its layer track? (from 10.3's resolver)
}
```

**The log is append-only and never popped.** Droppability is *derived* — a pass is droppable if any of its curves still exist in the composition. That one choice buys three things for free:

1. Dropping needs no bookkeeping: the curves vanish, so the entry stops being droppable.
2. `Ctrl+Z` restoring a dropped pass makes it droppable **again** automatically, with no undo hooks or flags — the curves are back, so it qualifies again.
3. Curves deleted or moved by other means (manual delete, cut, move-to-track) age entries out naturally instead of leaving dangling ids.

## Implementation

### 1. Pure pass-log module (new, unit-testable)

New `src/model/pass-log.ts` — keeps this logic out of `main.ts` per the backlog's standing note:

- `findDroppablePass(log: CommittedPass[], comp: Composition): { pass, surviving: string[] } | null` — walks newest → oldest, returning the first pass with at least one curve still present, plus exactly which of its curve ids survive (a partially-deleted pass drops what's left).
- `applyDrop(comp, pass, surviving): { curvesRemoved: number; trackRemoved: boolean }` — removes those curves from their track; then removes the track only if `pass.createdTrack && track.curves.length === 0`.

### 2. Store: `removeTrack(trackId)`

New mutator, and the one place real care is needed — this is the first code path that deletes a track, so every reference to a track id has to be considered:

- `selectedTrackId` → fall back to another track (or null) and clear curve/point selection.
- `midiArmedTrackId` → disarm if it pointed here.
- `harmonicPrism.projectionSourceId` → clear if the projection source lived on this track.
- Planchettes carrying `trackId` → drop them.
- 10.3's `currentLayerTrackId` (main.ts) → clear if it pointed here, so the next commit opens a fresh layer.
- Playback: `trackPlaybacks` holds a pool for the removed track. `adoptNewCurves` (10.2) only *adds*; stale pools are already handled on the next `play()` by `reconcileTrackPools`' stale-track disposal, and a pool with no curves schedules nothing, so this is benign — worth a confirming look, not new work.

### 3. The action

`dropLastPass()` in main.ts:

1. `findDroppablePass(passLog, comp)`; if none → toast "No performed pass to drop" and return.
2. `history.snapshot()` — one entry, so `Ctrl+Z` restores the whole pass including its track.
3. `applyDrop(...)` inside `store.mutate`.
4. Toast naming what went: the track name when the layer was removed ("Dropped Layer 3"), otherwise the curve count.
5. `bgDirty = true`.

Registration: `commitFinalizedCurves` appends one entry per pass, with `curveIds` from the committed curves and `createdTrack` from 10.3's resolver. Clear the log wherever `composeEngine.clearAllPhrases()` is called for composition load/new.

### 4. UI / docs

- `U` in the keydown handler (guard `!ctrl/meta/alt`, ignore `e.repeat`, respect the input-focus guard).
- [help.html](../../help.html): document `U` as "drop last pass — the live-looper *undo last layer*", the walk-back behavior, that `Ctrl+Z` brings a dropped layer back, and that it works with Layer mode off (curves only).

## Tests & verification

**Unit — new `src/model/pass-log.test.ts`:**
- `findDroppablePass` returns the newest pass; walks past a pass whose curves were all deleted; returns only surviving ids for a partially deleted pass; returns null for an empty log and for an all-stale log.
- `applyDrop` removes the curves; removes a created-and-now-empty track; **keeps** a track when `createdTrack` is false; **keeps** a created track that still holds other curves; reports accurate counts.
- Re-finding after a drop returns the *previous* pass (the walk-back chain).

**Unit — store:** `removeTrack` clears `selectedTrackId`, disarms MIDI, and clears a projection source pointing at the removed track.

**Full suite:** `npx tsc --noEmit` + `npx vitest run` green. The pass log is runtime-only, so the golden format test must not move.

**Manual (dev server, port 5187):**
1. Layer mode on, jam, keep three passes → `U` three times peels `Layer 3`, `2`, `1`, each disappearing from canvas and track panel.
2. `Ctrl+Z` after a drop restores both the curves and the layer track, and `U` can drop it again.
3. Drop with Layer mode off → the last pass's curves go, the selected track stays.
4. Drop a pass, then manually delete an earlier pass's curves, then press `U` → it skips the manually-deleted pass rather than erroring.
5. Drop the layer that was the MIDI-armed track → arm clears, no console errors, recording can be re-armed.
6. Drop while the transport is running → audio for that layer stops, others keep looping.
7. `U` with nothing performed → toast, no state change.
8. Add a curve manually to a layer, then drop that pass → the pass's curves go, the track and your added curve stay.

## Out of scope

A redo-layer key (`Ctrl+Z` covers it), a transport button, dropping *individual* curves within a pass (ordinary select + Delete), reordering layers, and dropping passes from a previously loaded file (the log is per app session by design).
